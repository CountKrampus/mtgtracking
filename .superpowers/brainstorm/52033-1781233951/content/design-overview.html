1 — Data Models

backend/models/ContentFlag.js

Existing models — fields added:

Model New fields
User isShadowBanned: Boolean (default false)
ForumThread isFlagHidden: Boolean  isShadowHidden: Boolean
ForumPost isFlagHidden: Boolean  isShadowHidden: Boolean
Message (chat) isFlagHidden: Boolean  isShadowHidden: Boolean

isFlagHidden = hidden pending mod review (auto at 3 flags).  isShadowHidden = hidden because author is shadow banned.  Shadow-banned users always see their own content.

2 — API Routes

Method Path Description
POST /api/forum/threads/:id/flag Flag a thread (requireAuth)
POST /api/forum/posts/:id/flag Flag a reply (requireAuth)
POST /api/messages/:id/flag Flag a chat message (requireAuth)
GET /api/admin/flags Flag queue — ?status=pending&page=1 (requireAdmin)
PUT /api/admin/flags/:id/review Approve or dismiss a flag (requireAdmin)
POST /api/admin/users/:id/shadow-ban Apply shadow ban (requireAdmin)
DELETE /api/admin/users/:id/shadow-ban Lift shadow ban (requireAdmin)

Auto-hide logic inside the flag POST handlers: count pending flags for this content — if ≥ 3, set isFlagHidden: true and create an in-app notification for each admin/editor user.

Shadow ban apply: sets User.isShadowBanned = true, bulk-sets isShadowHidden: true on all their existing forum threads, posts, and messages. Lift reverses it. New posts from a shadow-banned user automatically get isShadowHidden: true in the POST handler.
